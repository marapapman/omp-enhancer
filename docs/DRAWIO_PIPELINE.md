# Draw.io Diagram Pipeline (drawio@365-skills)

Contract for the draw.io diagram pipeline: all figures are drawn with `drawio-skill` (the `drawio` plugin of the `365-skills` marketplace, plugin ID `drawio@365-skills`). task draws the figure once and exports the evidence set (preview PNG, cropped single-page vector PDF, final repaired PNG); one independent reviewer (Main with image input, or a task that did not draw the revision) reviews the actual exports read-only in one pass — checking node/edge semantics, edges pressed onto each other (压线), edges crossing through boxes (穿框), collinear overlapping edges, clipped labels, font size at the physical print width, alignment, grouping margins, reading direction, and gray-scale distinguishability; task applies at most one local fix round and re-exports; the same reviewer then confirms against the fresh exports that the recorded findings are resolved and no new regression was introduced — this confirmation is not a second review pass or a new design round. Main retains setup authorization and final acceptance only. There is no repeated iteration. This is the default and only pipeline for architecture, block-diagram, flowchart, decision-flow, and deploy-pipeline figures.

All user-facing diagram text — node and edge labels, captions, annotations, narrative prose, and UI copy — is written or revised by the language-matched `writer` or `zh-writer` text tool; mixed-language output calls both. Main calls the text tool and integrates the returned copy verbatim. `task` and the reviewer may map, inspect, and report text, but must not draft or alter it. Text findings return to the matching text tool.

## Pipeline
1. Main fixes audience, target language, information claims, real nodes and directed relations (including conditions and grouping meaning), target paths, physical print width, and any names, math symbols, or terms that must not change. When the user provides an existing `.drawio`, the author reads it first and keeps its node IDs and coordinate conventions. Main also names the hero node or path and the lead decorative hue (blue #1668B5 or amber #E08A1E), and, unless the user asked for vector-only or text-only output, pre-generates one coherent house-style icon family with the native `generate_image` tool (style board as input, one recipe for every icon), adding Iconify glyphs for standard technical symbols; the plan lists the generated images with a one-line cost note and records provenance.
2. After `writer`/`zh-writer` returns the approved copy, task derives a stable node/edge ID list from the source material, maps the text verbatim, and draws once following `drawio-skill`: author the `.drawio` source and export the evidence set — a preview PNG (no `-e`, longest side <= 2000), a cropped single-page vector PDF (`--crop -e`), and a final PNG (`-e -s 2`) repaired with the skill's `repair_png.py`. Structure validation (`validate.py`) and font/box estimation belong to this authoring step.
3. One independent reviewer (Main with image input, otherwise an image-capable task that did not draw the revision; a text-only task model cannot read the exports) reviews the actual exports read-only in one pass: node/edge semantics, edges pressed onto each other (压线), edges crossing through boxes (穿框), collinear overlapping edges, arrow attribution, arrowhead size against the visible shaft (arrowheads small on a shaft of at least 3× their length), text clipping, font size at the physical print width, alignment, grouping margins, reading direction, gray-scale distinguishability, the color quota (white/black base, no gray or pale fills, small saturated accent blocks from the fixed palette (red #D5171A failure/risk, teal #037870 success/verification, blue #1668B5 and amber #E08A1E decorative-only), no AI rainbow per-element/per-category color assignment), and the aesthetic recipe (a hero about 1.3–1.6× the area of supporting nodes, content filling about 65–85% of the frame, palette ink at roughly 5–12% with semantic accents threaded along the key message, one consistent icon family, badges anchored to their node, three stroke tiers and two type weights). Findings name node/edge IDs, location, and one executable local fix. The reviewer does not edit the XML and records advisory findings only.
4. Supported structural findings get exactly one local fix round by task on the `.drawio` source (keeping other node/edge IDs and positions), then a re-export of the same evidence set; text findings return to the matching `writer`/`zh-writer` instead of being edited by task or Main. The same reviewer confirms against the fresh exports that the recorded findings are resolved and no new regression was introduced — this confirmation is not a second review pass or a new design round. Remaining findings are reported as limitations instead of triggering another round.
5. Deliver the `.drawio` source plus the exports the task actually needs (default for paper/report figures: `.drawio` + cropped vector PDF + clean PNG). Main retains setup authorization and final acceptance only.

## Boundaries

- The skill's internal self-check and scripts (e.g. `validate.py`) belong to the drawing step; the QA is exactly one read-only review pass plus at most one fix round and one fresh-evidence confirmation of the recorded findings (not a second review pass). This plugin's chain does not stack the external skill's own user-approval loop or its self-check-fix rounds on top.
- The draw.io desktop CLI requirement comes from the skill; when it is unavailable, follow the skill's fallback (browser URL or XML-only delivery).
- This is advisory guidance, not a hard gate, router, fixed fanout, automatic loop, or completion authority.

## Retired pipelines

The in-repo `drawio-diagram` skill, its bundled `check-drawio-layout.mjs` geometry checker, and the drawio MCP route (`create_diagram` / `open_drawio_xml`) are retired. The Mermaid (`mermaid_render`) and SVG (`svg-flowchart`) pipelines were retired earlier.
