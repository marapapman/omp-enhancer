# 中文严格写作状态机

中文严格写作采用读取来源、拟稿、自检和交接的证据矩阵。每条引用、每个数字和事实论点都应有可观察来源。用户明确要求严格模式时，每段处理完就重置上下文；Main 按长文协议把现稿切成 `chunk-001` 顺序的块时，块与块之间默认使用新的 `zh-writer` 子任务。不得以用户没有要求隔离为由，拒绝一个有界的块任务。

块任务只处理块内的段落，证据矩阵在块内照常逐段执行；章节主线、术语定义和用户已批准的写作风格通过只读邻接上下文和冻结的风格包传入，不靠恢复前一块的会话。中文单块最多 2,000 个非空白字符，超过即默认拆分，这个上限不作为交付物的篇幅限制，也不作为运行时门禁。

本技能沿用 `zh-writer` 文本工具的内置中文风格基线，局部方法继承当前任务所选文体（技术说明、教学讲解、学术正文、科研成果凝练、幻灯片正文、日常沟通），不把所有任务恢复成同一种论文腔；只在用户或目标文档给出的格式内补充局部做法。本 Skill 的局部语言风格清单只是补充；与内置中文风格基线冲突时，以基线为准，用户显式指定的风格仍优先。

## 工作流边界

只在 Main 选择工作流 `writing`、加载其精确 workflow reference 和本 Skill，再把任务交给 `zh-writer` 文本工具调用后使用本 Skill。这是 `zh-writer` 文本工具的有界局部方法，不选择或调度 Agent。不要递归 fork、spawn 或 delegate。Main 保留父级 TODO、集成、最终验证和面向用户的交付权。

证据矩阵只是 writer 局部自检，不能满足或替代独立 `zh-checker` delivery。只做一次有界局部处理；不启动自动修复循环，也不创建完成门禁。把段落、矩阵、来源和未解决缺口返回给 Main。

`zh-writer` 文本工具始终只交付建议稿。返回完整建议文本；有界补丁更清楚时，使用
SEARCH/REPLACE 块或 unified diff。Main 保留权限决策和实际文件修改。不要创建或
持久化目标文档、研究产物或 review log。

## 适用场景

- 写实验结果、数据章节、或任何含引用和数值论点的内容
- 用户明确要求"严格模式"或"无幻觉"写作
- 多段落文档中段落间不允许上下文漂移

## 核心流程与段落循环

证据矩阵按段执行。用户明确要求严格段落隔离时，每段独立处理，段后重置上下文；Main 按长文协议划块时，块内段落仍按本流程逐段执行，块结束时终态交付，下一块由 Main 派成新的子任务，新子任务不恢复本块会话。不属于这两种情况时，把本流程作为质量建议，不强制每段开启新会话。

### 1. 读取 — 只读当前需要的

只读当前这一段需要的源数据。事实证据只依赖当前段落的来源，上一段的主张不替代本段证据。可以读：
- 目标文档（扫描章节结构、术语定义和相邻段落的衔接）
- 当前段落的源文档、数据表或引用文献
- 章节的元数据/描述（如果有）

只有用户或 host 授权网络访问且存在实时网络能力时，才使用网络。本地证据不足而任一条件不满足时，不要联网，把来源缺口返回给 Main。

### 2. 写作 — 恰好一段

默认写目标章节下的一个自然段，长度服从语义完整与证据表达。只有用户明确要求段落节点模板，或目标文档明确把六级标题用作段落主题句节点时，才按下面的节点结构输出：

```markdown
###### 标题 — 主题句

正文，含正确的 `[@引用]` 标记。
```

约束：
- 模板生效且长度上限明确给出时，主题句 ≤50 字符
- 正文语义完整，不为了变短而拆散论证
- 引用必须精确，从来源复制，不要改写引用标签
- 来源元数据和建议的 review-log 条目随结果交付。不要在文档中用 HTML 注释

### 3. 自检 — 建议验证矩阵

| 检查项 | 通过/失败 |
|--------|-----------|
| 段落节点模板生效且长度上限明确给出时，标题 ≤50 字符 | — |
| 正文语义完整，没有机械短句化；长度检查仅在模板生效时执行 | — |
| 正文中每个 `[@...]` 引用在来源中存在 | — |
| 交付结果或已授权的 review log 中有来源真实路径 | — |
| 没有超出源数据支持的论点 | — |
| 没有翻译腔表达 | — |
| 没有 AI 味表达 | — |
| 没有破折号 | — |
| 冒号、括号、黑体使用合理 | — |

在这一轮 `zh-writer` 文本工具任务内，修复能从现有证据解决的检查项。无法解决的项目写入局限说明，并只继续任务指定的范围。

### 4. 交接 — 遵守操作授权

把完整段落建议和有界插入补丁返回 Main。是否在获授权的集成阶段持久化，由 Main 决定。

### 5. 重置与交接

用户明确要求严格模式时，处理完当前段落就停止，并把以下交接返回给 Main：

> 当前段落已完成。后续隔离任务可以从[章节名]继续。

Main 按长文协议派块时，交回块标识与来源版本，把本块完整建议稿作为终态交付后停止。下一块由 Main 派成新的 `zh-writer` 子任务，本任务不续写下一块，也不询问用户是否继续。

## 证据边界

不得生成占位或虚假的事实、引用、测量结果或数字。证据不足时，省略或标明不受支持的主张，并把准确的证据缺口返回给 Main。

## 中文写作规范

写作时遵守 `plain-chinese-writing` 技能中的相关规范。以下是要点提醒。

### 标点规则
- 破折号完全禁用
- 冒号限制使用（列举三项以上、引出定义时可用）
- 括号限制使用（缩写定义、编号可保留）
- 黑体限制使用（关键词定义、列表标签可保留）

### 语言风格
- 平直、准确，判断保持克制，默认按通用书写基线写：规范自然的书面表达，段首先写问题或对象，动词具体并交代机制，结果带数字和比较对象，主语按任务指定；只在科研成果凝练与学术正文任务里才用科研叙述体（针对开段、结果显示、贡献收尾、必要长复句）；句长服从信息关系，不机械拆句，不凑字数，不把简洁当作独立目标
- 多用动词，少用抽象名词
- 语义完整，长短相间
- 每句围绕表达重点，只保留新事实、必要限定和关键逻辑关系；冗余先删除再改写，不用更长的解释替换，读者可推断的环节合理省略
- 注意中文特征：主题突出、意合衔接、主动优先
- 不为了规避标点规则而机械拆句
- 保留必要的限定、转折和承接信息
- 不机械使用"不在于……而在于……"转折模板
- 直接写具体困难、原因和后果，少用模板化转折
- "的"字不要连用三个以上

### 翻译腔和 AI 味
- 不堆叠名词，不滥用"进行""实现""基于"
- 不用英文语序，不用过多框式介词
- 不写空泛开头、泛化评价、套话结尾

## 反面模式

用户明确要求严格隔离模式时：

- 每个隔离循环只处理一段。
- 不把上一段的引用或来源当成本段事实证据。
- 来源中找不到引用标签时，删去对应论点或标明证据不足。
- 对当前段落做一次自检。
- 下一循环只加载该段所需上下文。

任何模式都不要把每个关键判断都写成"不是……而是……"或"不在于……而在于……"。

任何模式都只完成受派的 `zh-writer` 文本工具局部方法。是否集成、要求独立 checker delivery 或开始另一项任务，由 Main 决定。
