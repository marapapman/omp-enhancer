# 中文去 AI 痕迹工具

扫描中文文档中的 AI 写作痕迹。实质性文档的规则应用按「一类特征一个独立任务」串行进行，绝不把所有规则混在一次修改稿里套用。只有用户明确要求逐项审查，或替换会改变含义时，才逐项确认。最后汇总修改前后差异。

writer 子 Agent 始终只交付建议稿。返回完整建议文本；有界补丁更清楚时，使用
SEARCH/REPLACE 块或 unified diff。Main 保留权限决策和实际文件修改。

核心原则：宁可误杀，不可放过。发现 AI 特征即改，一次出现即改；只有引文、标题、专有名词、讨论词本身的段落、2022 年 11 月 30 日之前的文本，以及作者本人的真实选择（具体不寻常的细节、复杂情绪、第一人称选择）受保护。

防副作用原则：不得把所有句子改短，不得把所有段落改成同一种节奏。破折号完全禁用。冒号、括号、黑体限制使用但不等于机械拆句。处理限定、转折和解释信息时，应优先保留语义完整，再调整到句首、句尾或并入主句。只有句子确实过长或层级混乱时，才拆成独立句子。

科研成果凝练体例外：用户明确要求科研成果凝练体时，论文发表列举和系统部署收尾是该体例的有意组成，不报告为机械列举或 AI 味。仍需核对输入证据；没有发表场所或部署证据时，不要补写。

写作规范详见 `plain-chinese-writing` 技能，本技能在此基础上专注于 AI 痕迹扫描与替换。

## 强度分级

AI 写作的特征强度不同。强特征和弱特征都一次出现即建议修改，宁可误杀，不可放过；只有引文、专名、时代特征和作者本人选择豁免。词表随模型版本变化，结构特征更稳定，所以先看结构再看词汇。每次修改后自查五个最容易残留的结构痕迹：否定式对偶、单句收尾、三连排比、破折号、黑体标签。

## 强特征（一次出现即建议修改）

### S1. 否定式对偶

「不是 X，而是 Y」「不仅仅是 X，更是 Y」「X 不在于……而在于……」「与其说 X，不如说 Y」，以及拆成两句的对照（「这并不意味着 X。它意味着 Y。」）。否定半句指向一个没人主张过的观点，让肯定半句听起来更重，却不增加信息。直接陈述观点。只有否定半句确实纠正读者实际持有的误解，或两半都承载信息时，才保留对照。

示例。

```text
修改前：这不是简单的性能优化，而是一次范式的重塑。
修改后：这次改动把训练开销降到了原来的三分之一。
```

### S2. 单句收尾与戏剧化短句

单独成段的一句话重复上段内容（「这才是真正的价值所在。」「值得深思。」），碎片排比（「没有模板。没有套话。没有废话。」），以及刻意断行强调。短句可以承担强调，但必须携带新信息。只重复的收尾删掉，碎片排比合并成一句有具体主张的句子。

### S3. 貌似深刻的说法

「真正的问题是」「本质上」「归根结底」「说到底」「X 是 Y 的语言」「X 的本质是 Y」。用被包装的具体判断替换格言。

### S4. 铺垫式开场

「让我们深入探讨」「接下来我们将展开」「需要说明的是」「值得强调的是」「话不多说」。删除铺垫，直接进入内容。

### S5. 与不存在的对手辩论

「这并不是说」「需要澄清的是」「有人可能会认为……但」「一个容易被忽略的做法是」。这些句子回应的是文中从未出现的异议，多半是早期草稿的残留。删除辩解；如果其中承载真实主张，直接写出该主张。

### S6. 意义拔高

「标志着……的新阶段」「具有里程碑意义」「开创了……先河」「为……奠定了坚实基础」「意义深远」「彰显了」「见证了」「诠释了」。保留事实，删掉拔高。结尾落在最后一个具体事实上；来源里有真实计划时用真实计划。

### S7. 理解承诺句

「理解了 X，Y 就好懂了」「把这个说清楚，A、B 和 C 就容易理解了」「X 是理解 Y 的钥匙」。整句谈读者的理解过程，不谈 X、Y 本身，是关于内容的元内容；「更容易理解」没有可比对象，不可验证。删除；正文确实依次讲 A、B 和 C 时改成路线图（「先讲 X，再看 A、B 和 C」）；存在真实依赖时写成具体事实（「A、B、C 都以 X 为基础」）。

### S8. 抽象复述回声

前半句讲完具体事实，后半句把同一事实抽象成带引号或名词化的概念再说一遍：「算筹、算盘就能做加减乘除。」「“会算”这件事人类很早就做到了。」后一句信息增量为零，只是把前一句抬高一层复述——是「具体＋升华」两拍句去掉全称升华词后的形态。删掉回声句；确有推进时换成新事实。不要给自己的常识陈述加引号或名词化成概念对象——人写讲义不会这么点题。

### S9. 宣布式过渡

「新的问题是」「真正的问题是」「这就引出了一个更深的问题」。替读者宣布"真正的问题"来了，而不是让事实自己把问题带出；口头讲课自然，落成文字就是旁白腔。删除；确有递进关系时写成具体事实（「在此基础上，还剩两个障碍」）。

### S10. 节奏对仗收尾

用两个或多个整齐对仗的短语收束句子、段落或页面：「够不够快、能不能自动」「更便宜、更安全、更可控」。对仗必须由内容挣得——每一项都是主张下真实且可独立成立的维度；删掉任何一项不损失信息的，整组删掉，直接说清那一个点。

## 弱特征（一次出现即建议修改）

### W1. 三连排比

「高效、稳定、可靠」「创新、协同、共赢」以及三项并列的例子。逐项检查是否各有独立信息；不足三项时合并或展开最有信息量的一项，超过三项时列出全部。含义确需三项时保留三项。

### W2. 重复句首

连续几句以同一主语开头，是按规则处理而不是按语感处理的表现。合并句子、更换主语，或以动作开头。不要禁用主语；保留的句子仍可以「她」开头。

### W3. 叠加限定

「可能或许在一定程度上会影响」「大概也许」。只保留来源支持、语义必需的限定；范围声明、法律与安全提示、真实纠错保留。

### W4. 被动与主语缺失

「数据被进行了清洗」「通过实验得到了验证」。中文主动优先；能让动作和施动者更清楚时改主动句。

### W5. 对称段落

每段开头一样、长度一样、结构一样，第二句展开、第三句转折。合并相邻短段、改写相同开头、变化句长。只在破坏原有论证顺序时停止。

## 拔高与借来的权威

事实通常没错，错在包装。保留事实，去掉包装。

### A0. 浅层评述小尾巴

「……，体现了……」「……，反映了……」「……，为……提供了支撑」「……，进一步印证了……」挂在事实句尾的渲染小尾巴，且来源不支持它声称的内容。事实句保留，小尾巴只在来源支持时保留；依附到具体人名（「某专家指出了深远影响」）不改变这一判断。

### A1. 推销语言

「坐落于」「令人心旷神怡」「丰富的文化底蕴」「不可多得的」「为……注入新动力」「焕发新的活力」「无缝衔接」。直接说它是什么。

### A2. 借用权威

「专家认为」「业内普遍认为」「多项研究表明」「有媒体报道」「备受关注」而不给出具体来源。用来源实际说过的内容；没有来源时删掉这条主张或这份清单。绝不虚构来源。缺少引用本身不算 AI 特征。

### A3. 模糊关联

「与……密切相关」「在……方面发挥了作用」「与……保持一致」而不说明具体关系。来源给出关系就写关系；来源没说时保留模糊表述，不虚构角色。

### A4. 系动词回避

「堪称」「可谓是」「作为……而存在」「扮演着……的角色」代替「是」「有」。直接用「是」「有」。

## 格式修饰

### F1. 黑体装饰

无信息量的加粗，以及「**粗体标签：** 描述」式列表。删除加粗；标签不承载信息时把列表改写成段落。关键词首次定义和列表标签的黑体保留。

### F2. 装饰性标题

每个标题都加书名号式点缀、emoji 或箭头装饰，每节之间一条分隔线，文档开头再重复一遍标题，只含其他标题的标题，跳级标题。标题只出现一次，去掉装饰。

### F3. 聊天残留

「希望这对你有帮助」「当然可以」「你说得对」「如果需要我可以继续展开」「以下是……」。删除外壳，保留内容。

### F4. 知识截止声明与臆测

「据现有资料……这可能说明……」「公开资料中未见记载，推测其……」。写清来源没有显示什么，或删掉这句话。绝不把猜测写成事实。

### F5. 标题重复正文首句

标题下面先用一句话复述标题（「## 性能」下面接「性能很重要。」）。删除复述句，直接写真正的内容。

### F6. 叙述旧版本

「本文取代了此前……的做法」属于变更记录和迁移说明，不属于描述当前行为的正文。写当前怎么做；提及旧版本只在变更记录里。

## 何时不处理

以下情况保留原文（这是仅存的豁免，不是默认门槛）：

- 引号内的引用、标题、专有名词，以及讨论这个词本身而不是使用这个词的段落。
- 2022 年 11 月 30 日之前的文本。
- 具体不寻常的细节（真实地址、特殊引语、只有作者能写出的细节）。
- 复杂情绪和未决张力（「我觉得基本可以，但有一点说不清的别扭」）。
- 有时代特征的引用、俚语、圈内梗。
- 作者能解释的第一人称选择。
- 真实的旁白、插入语或自我更正。
- 信件和评论的开头称呼与结尾署名早于聊天机器人。

单一特征一次出现即构成修改依据；引文、专名、时代特征和作者本人选择仍然保留。人的写作也在吸收 AI 的习惯，误伤由作者复核兜回，漏判无人兜底。

## 语义锚点

频率和强度限定、模态、范围、否定、比较和因果方向、数字和单位、引用和标识符，以及 LaTeX 数学、交叉引用、命令和结构都是语义锚点。除非用户或证据明确要求，否则保持不变。拟稿后把结果与原文比对一次，发现漂移时报告建议，不静默调整。

## 触发场景

用户要求"去 AI 味""去翻译腔""让文字更自然""改得更像人写的""润色中文"等。也适用于审查输出时发现文档过于模板化。

## 扫描模式

对每个模式，给出原文、问题诊断和建议替换。

### 1. 词汇规范化（意图驱动）

凡是无实质信息量的情感渲染性表达，或试图通过华丽辞藻掩盖逻辑空洞的词汇，均应替换为具体、客观的学术描述。

| 原文 | 问题 | 替换为 |
|------|------|--------|
| "毋庸置疑" | 情感渲染 | 删除或改为具体陈述 |
| "不可磨灭的贡献" | 过度拔高 | 具体说明贡献是什么 |
| "范式转移" | 花哨 | "转变"或具体说明变化 |
| "颠覆性" | 夸大 | "新的"或具体说明不同之处 |
| "令人惊叹" | 情感渲染 | "显著"或给出具体数据 |
| "为了解决这一痛点" | 互联网黑话 | "针对上述问题" |
| "展现了令人惊叹的能力" | 夸大 | "表现出显著的性能提升" |
| "深刻" | 空泛 | 具体说明深刻在哪 |
| "切中要害" | 花哨 | "准确" |
| "本质"（非哲学语境） | 空泛 | "核心"或具体说明 |

保持核心专业术语的准确性，绝对不要为了"去 AI 味"而随意替换领域内的专有名词。

### 2. 句式与结构自然化（去翻译腔与机械感）

| 模式 | 检查什么 | 修改前 → 修改后 |
|------|----------|-----------------|
| **英式长定语** | "一个…的…的…"连续修饰结构 | "一个面向大规模数据的分布式处理系统" → "一个分布式处理系统，专门面向大规模数据" |
| **被动语态过多** | 中文学术写作少用"被"字句 | "…被用来优化…" → "采用…优化…" |
| **机械列举** | "首先…其次…最后…"或"1. 2. 3." | 融合成逻辑连贯的段落。但若列举在当前语境下逻辑更清晰，如陈述算法核心步骤，可酌情保留 |
| **机械转折** | "因此，问题不在于……而在于……"，"核心困难不在于……而在于……" | 只有需要纠正误解时才保留对照句。多数情况下直接写具体困难、原因和后果 |
| **过度使用"进行"** | "对……进行分析" | "对数据进行了清洗" → "清洗了数据" |
| **过度使用"实现"** | "实现了性能提升" | "提高了性能" |
| **过度使用"基于"** | "基于上述分析" | "根据上述分析" |
| **名词堆叠** | 连续多个名词的偏正结构 | "数据驱动的基于深度学习的智能分析系统" → "用深度学习分析数据的系统" |
| **抽象主语过多** | 主语是抽象名词短语 | "实验结果的提升表明了模型设计的有效性" → "实验结果表明模型设计有效" |
| **框式介词过多** | "在……方面""对于……来说""关于……的问题" | 能省则省，直接说 |
| **"的"字连用** | 连续三个以上的"的" | 重组句式 |

### 3. 空泛开头

| 原文 | 替换为 |
|------|--------|
| "近年来，随着人工智能技术的快速发展……" | 直接说问题或研究对象 |
| "在当今数字化时代……" | 直接说背景中最具体的一点 |
| "随着社会的不断进步……" | 删除，直接进入内容 |
| "在复杂多变的现实环境中……" | 直接说具体环境 |
| "随着……的不断发展……" | 直接说事实 |

### 4. 过度结构提示

| 原文 | 替换为 |
|------|--------|
| "本文将从以下几个方面展开。" | 删除，直接进入内容 |
| "接下来，我们将深入探讨。" | 删除 |
| "综上所述，" | 删除或改为一句总结 |
| "总而言之，" | 删除或改为一句总结 |
| "本文旨在深入探讨……" | "本文研究……"或"本文提出……" |

### 5. 泛化评价

| 原文 | 替换为 |
|------|--------|
| "该方法具有重要意义。" | 具体说明意义是什么 |
| "发挥着重要作用。" | 具体说明起什么作用 |
| "提供了有益参考。" | 具体说明参考什么 |
| "具有广阔前景。" | 说明可用于什么地方 |
| "展现出巨大潜力。" | 给出具体数据或结果 |

### 6. 套话结尾

| 原文 | 替换为 |
|------|--------|
| "未来仍需进一步探索。" | 写具体的后续工作 |
| "相信该方法将在更多领域发挥价值。" | 删除或写具体的应用方向 |

### 7. 格式问题

| 模式 | 检查 | 处理 |
|------|------|------|
| **破折号** | 完全禁用—— | 保留原意后改写为普通句式。必要时拆句 |
| **冒号滥用** | 非列举、非定义场景下的冒号 | 改为自然承接句。列举三项以上或引出定义时可保留 |
| **括号滥用** | 括号内塞了长句或完整解释 | 把补充信息并入主句、放到句首或句尾。缩写定义和必要编号可保留 |
| **黑体滥用** | 用黑体代替表达强度 | 删除黑体标记。关键词首次定义或列表标签可保留 |
| **插入语** | 句中频繁插入解释 | 保留限定信息，调整到句首、句尾或并入主句。必要时拆句 |
| **Markdown 标记** | Word 粘贴场景中的 `**``*``#` | 删除所有 Markdown 标记 |

### 8. 对称段落

每段开头一样、长度一样、结构一样时，才判断为对称段落。处理时可以合并短段落、改写相同开头、变化句长，但不要为了变化而破坏原有论证顺序。

## 处理流程

实质性文档按「一类特征一个独立任务」串行执行。只有当扫描确认全文仅命中一个特征家族时，才允许一次直接完成；命中两个及以上家族一律走逐家族任务链。

1. **扫描任务。** 通读全文，产出特征家族清单：哪些家族实际出现，各附一处原文例证，按强度排序。同时看段落形态、列表形态和标题结构：拆成两句的对照、三个并列例子、每节结尾同一句式，是同一特征在更大尺度上的出现。没有发现的家族在后续步骤跳过。

2. **逐家族任务，严格串行。** Main 按扫描顺序逐个派发任务：任务 N 返回并通过语义锚点核查（限定、模态、范围、否定、方向、数字、单位、引用不变；不新增不丢失事实）后，才派发任务 N+1。每个任务只处理自己那一个家族，作用于完整当前文本（含此前任务已采纳的修改），保留全部有依据的主张；可精简平淡段落、合并拆分段落、调整结构，但不得增删信息。返回 SEARCH/REPLACE 块或 unified diff，范围限于本家族。

3. **任务内自查。** 每个任务改写后通读一遍：本家族的痕迹是否清零；改写是否增删了任何事实、数字、日期、引用或主张。

4. **输出对比。** Main 按顺序汇总各家族结果，把会改变含义的替换列为作者决定，并负责持久化。所有发现处理完后展示：
   - **修改前** — 完整原文
   - **修改后** — 完整修改后文本
   - **变更统计** — 按模式类型统计替换数量

## 修改阈值（关键）

- 如果文本已经自然、严谨且没有明显 AI 特征，保留原文
- 对于高质量的输入，给出明确肯定："原文表达严谨自然，无明显 AI 痕迹，建议保留。"
- 不要为了换词而换词
- 不要把自然的中长句全部改成短句
- 不要机械使用"因此……不在于……而在于……"这类转折模板
- 不要删除原文中的限定、转折、因果和承接信息

## 可选逐项输出格式

只有用户明确要求逐项确认时才使用以下格式：

```
--- 发现 1 / N ---
模式：[模式名称]
原文：[带上下文的原文引用]
问题：[具体说明为什么这是 AI 痕迹]
建议：[替换文本]
是否替换？（y/n）
```

所有发现处理完后：

```
--- 修改前 ---
[完整原文]

--- 修改后 ---
[完整修改后文本]

--- 变更统计 ---
- 翻译腔：3 处替换
- AI 味：2 处替换
- 套话：1 处替换
...
```
