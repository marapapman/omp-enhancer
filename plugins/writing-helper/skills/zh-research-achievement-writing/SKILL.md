# 中文科研成果凝练写作 Skill

## 0. 适用范围

本 Skill 是 `writing` 中处理“科研成果凝练体” prose deliverable 的局部方法。只有同时满足以下条件时才使用。

1. 用户明确要求撰写、改写或凝练科研成果、研究方向、项目业绩或个人学术简介，并要求类似科研成果简介的行文风格。
2. Main 选择工作流 `writing`、加载其精确 workflow reference 和本 Skill，再把任务派给 `zh-writer` 子 Agent 后，才在 writer assignment 中使用本 Skill。

这是受派 writer 子 Agent 的有界局部方法，不选择或调度 Agent。不要递归 fork、spawn 或 delegate。Main 保留父级 TODO、集成、最终验证和面向用户的交付权，并负责 finding disposition。

没有匹配的 writer、容量不足或无法形成安全完整的任务时，Main 记录该限制，并可采用工作流中的安全的直接 fallback。

writer 子 Agent 始终只交付建议稿。返回完整建议文本；有界补丁更清楚时，使用 SEARCH/REPLACE 块或 unified diff。Main 保留权限决策和实际文件修改。

本 Skill 不用于普通中文润色、去 AI 味、完整七维审查、语义逻辑审查、邮件、日常说明或一般论文段落。普通文本仍使用 `plain-chinese-writing`，真正的去 AI 味任务使用 `zh-format-humanizer`，保守润色使用 `zh-writing-polish`。

---

## 1. 行文目标

科研成果凝练体采用正式、客观、凝练的成果介绍方式。直接写技术问题和已有缺点，不铺垫空泛背景，不使用夸张评价。整段优先保持下面的顺序：

问题或缺点 → 技术引入 → 方法提出 → 应用任务 → 成效 → 论文成果 → 系统开发与部署。

多项工作可以放在同一段中，用分号并列方法和结果。每个分句只保留方法、应用和可核验成效，不添加空洞的意义判断或套话结尾。

---

## 2. 可复用句式骨架

### 2.1 技术突破与应用

先指出现有方法或系统的缺点，再连接技术引入、方法提出和应用任务。优先使用无主语因果链：

“通过引入 X，克服了 Y 的 Z 缺点，提出一种融合 A 与 B 的方法，应用于 C、D 任务。”

### 2.2 成效

方法之后紧接效果，使用输入提供的指标和范围，不把定性判断写成定量结论：

“该方法克服了 Y 的 Z 缺点，降低了 C 和 D 算法的误差。”

保留“最高”“超过”“达到”“约”等强度限定、数字、单位、比较关系、否定范围和因果方向。不要把“最高降低 90%”改成“降低 90%”，也不要把“超过 95.5%”改成“达到 95.5%”。

### 2.3 论文成果

输入明确提供会议、期刊和年份时，使用会议或期刊缩写加两位年份的列举格式：

“相关工作发表于 VENUE’YY、VENUE’YY。”

只写输入明确提供的发表场所、年份、论文名称和引用编号。没有发表场所或部署证据时，不要补写。不要根据论文标题、作者或主题猜测发表 venue、年份或论文状态。

### 2.4 系统开发与部署

输入明确提供系统开发、支持范围、部署地点或规模时，使用成果收尾句：

“基于所研究的 X 算法，开发并部署一种基于 Y 的系统，支持……判断，已部署地点 N 座楼宇。”

没有部署证据时，不写“开发并部署”、已部署地点、覆盖数量、用户规模或运行范围。论文发表列举和系统部署收尾是本体例的有意组成，不因其并列或格式化而自动判断为 AI 味、机械列举或套话；仍需检查事实证据和语义准确性。

---

## 3. 事实和语义边界

不得生成占位或虚假的事实、引用、测量结果或数字。证据不足时，省略或标明不受支持的主张，并把准确的证据缺口返回给 Main。只有用户或 host 授权网络访问且存在实时网络能力时，才使用网络。

修改或凝练已有内容前，记录频率和强度限定、模态、范围、否定、比较和因果方向、数字和单位、引用和标识符，以及 LaTeX 数学、交叉引用、命令和结构。这些都是语义锚点，不能为了压缩篇幅删除。拟稿后只与原文比对一次。

不得为了套用骨架而补充输入没有提供的应用、效果、发表信息或部署信息。多个研究方向之间没有共同证据时，分别陈述，不强行合并成一个统一系统或统一结论。

---

## 4. 局部自检与交接

下列检查只属于 writer 局部自检。写作者的局部自检不能替代独立 checker，也不能满足或替代独立 `zh-checker` delivery。只做一次有界局部处理；不启动自动修复循环，也不创建完成门禁。把完整建议稿、保留的引用和仍缺失的证据返回给 Main。

- 是否先写问题或缺点，再写技术、方法、应用和成效。
- 是否保留“最高”“超过”“达到”“约”等限定及其数字、单位和引用。
- 是否只在输入提供发表信息时写“相关工作发表于……”。
- 是否只在输入提供部署证据时写系统开发、部署地点和规模。
- 是否把论文发表列举和部署收尾用于用户明确要求的科研成果凝练体，而不是普通 prose。
- 是否没有空泛开头、泛化评价、套话结尾、翻译腔或未经证实的事实。
