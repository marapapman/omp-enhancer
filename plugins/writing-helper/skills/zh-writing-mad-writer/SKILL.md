# 中文快速写作技能

按 Main 授权的一块写中文文档正文，默认执行一轮写、查、改。读取叙事和文献上下文，完成目标章节，做 7 维度聚焦检查，能修的直接修，修不了的标记出来。只有用户明确要求迭代修订时才开始下一轮。

本技能沿用 `zh-writer` 文本工具的内置中文风格基线，局部方法继承当前任务所选文体（技术说明、教学讲解、学术正文、科研成果凝练、幻灯片正文、日常沟通），不把所有任务恢复成同一种论文腔；只在用户或目标文档给出的格式内补充局部做法。本 Skill 的局部语言风格清单只是补充；与内置中文风格基线冲突时，以基线为准，用户显式指定的风格仍优先。

## 工作流边界

只在 Main 选择工作流 `writing`、加载其精确 workflow reference 和本 Skill，再把任务交给 `zh-writer` 文本工具调用后使用本 Skill。这是 `zh-writer` 文本工具的有界局部方法，不选择或调度 Agent。不要递归 fork、spawn 或 delegate。Main 保留父级 TODO、集成、最终验证和面向用户的交付权。

下列七个维度只是 writer 局部自检，不能满足或替代独立 `zh-checker` delivery。只做一次有界局部处理；不启动自动修复循环，也不创建完成门禁。把修订文本、证据、局限和作者决策返回给 Main。

`zh-writer` 文本工具始终只交付建议稿。返回完整建议文本；有界补丁更清楚时，使用
SEARCH/REPLACE 块或 unified diff。Main 保留权限决策和实际文件修改。不要创建或
持久化目标文档、研究产物或 review log。

## 输入

- paper.md（必须有）— 当前文档
- 受派块只在 Main 按长文协议划分任务时出现。当前文档可能只以这一块到达，随附 `chunk-001` 编号、目标文件与来源版本、段落或页或 shape 范围、只读邻接上下文、冻结的风格包和验收项；此时交付单元就是这一块，其余块由其他子任务完成
- .pi/research/storyline.md（如果存在）— 研究叙事
- .pi/research/literature.md（如果存在）— 相关工作上下文
- 已确认的故事快照（仅当任务显式给出路径与版本），如 .storyline/exports/r<版本>/storyline.md 与同目录的 story.json

任务显式传入已确认的故事快照路径与版本时，该快照就是交付物的故事来源，优先于 .pi/research/storyline.md 以及目标现稿的旧大纲。普通局部修改仍以目标现稿的当前版本为准。据快照写作时，按快照的节点结构和层级组织章节与段落，不把每个节点强制转成固定层级的标题。交付说明里列出所有节点 ID 的覆盖情况，未使用的节点写明原因并交回用户，不得静默丢弃证据。

只读取任务已提供的输入和 host 授权的安全路径。约定路径本身不代表可以探测或修改。

## 工作流程

### 第 0 轮：准备

读取已提供的输入。识别空章节（空白或 `[TODO]`/`[FILL]` 标记）。如果缺少相关工作文献，从 storyline 提取 3-8 个关键词。只有用户或 host 授权网络访问且存在实时网络能力时，才使用网络。两个条件都满足时，每个关键词最多查看三个结果，并在引用前读取选中的来源。否则只使用本地证据，并把来源缺口返回给 Main。

### 默认一轮：写 → 查 → 改

**1. 写作冲刺** — 只处理受派范围内空/稀疏的段落，长文按块派任务时就是 Main 划定的这一块。读取上下文、只读邻接上下文和 `<!-- description: ... -->`，写正文并引用文献。默认写自然段，长度由任务和论证需要决定。只有用户明确要求段落节点模板，或目标文档明确把六级标题用作段落主题句节点时，才在第 6 级标题写主题句；长度上限也仅在用户或文档规范明确给出时执行。本块写完就进入自检和有界修复，块结束即终态交付。一轮指这一块，不是整份文档的一次往返，后续块由 Main 另派新的 `zh-writer` 子任务。

**2. writer 局部多维自检** — 运行全部 7 项检查。每个发现引用具体证据。不捏造问题。

| 维度 | 检查内容 |
|------|----------|
| 问题 | 定义清楚？重要性有证据？关联具体需求？ |
| 新颖性 | 与已有工作区分？指出具体不足？ |
| 深度 | 解决了有难度的技术问题？ |
| 逻辑 | 论证一致？论点有证据？无跳跃或矛盾？ |
| 清晰度 | 术语有定义？语言精确？无翻译腔和 AI 味？ |
| 评估 | 实验对应研究问题？基线合理？指标合适？ |
| 数据 | 引用真实？复现路径清晰？ |

严重程度：CRITICAL（影响整个论点）/ IMPORTANT（需要修复）/ MINOR（改进建议）。

**3. 修复有证据支持的局部问题** — 在受派的一轮内定义不清术语，用有证据支持的具体表达替换模糊措辞，扩展有依据的稀疏内容，并清理格式。不得根据猜测填补事实缺口。需要真实实验数据、领域专家判断、用户决定或解决矛盾需求的问题返回给 Main。

**4. 决定下一步** — 交付改进后的章节并列出证据或作者决策缺口。可以建议再做一轮，但不要自动开始。

### 可选摘要

```
轮次：N。章节：[列表]。已处理问题：[数量]。
剩余：[不可修] 第 X 节 — 描述。
下一步：[用户应该做什么]。
```

## 证据与操作边界

- 不得生成占位或虚假的事实、引用、测量结果或数字。证据不足时，省略或标明不受支持的主张，并把准确的证据缺口返回给 Main。
- writer 的所有效果都在会话中以建议文本或有界补丁交付；获授权后的持久化由 Main 负责。

## 中文写作规范

写作时遵守 `plain-chinese-writing` 技能中的相关规范。以下是要点提醒。

### 标点规则
- 破折号完全禁用
- 冒号限制使用（列举三项以上、引出定义时可用）
- 括号限制使用（缩写定义、编号可保留）
- 黑体限制使用（关键词定义、列表标签可保留）

### 语言风格
- 平直、准确、自然，判断保持克制，默认按通用书写基线写：规范自然的书面表达，段首先写问题或对象，动词具体并交代机制，结果带数字和比较对象，主语按任务指定；只在科研成果凝练与学术正文任务里才用科研叙述体（针对开段、结果显示、贡献收尾、必要长复句）；句长服从信息关系，不机械拆句，不凑字数，不把简洁当作独立目标
- 多用动词，少抽象名词
- 语义完整，长短相间
- 每句围绕表达重点，只保留新事实、必要限定和关键逻辑关系；冗余先删除再改写，不用更长的解释替换，读者可推断的环节合理省略
- 不写回指被动尾句（完整主句后用逗号接「前置宾语＋由＋回指施事＋动词」的小句，如「Documents 和 report.txt 拼成一条路径，斜杠由它补上」），把尾句的动作和新对象用「并」接进主句，施事能还原时写一次名称，还原不出来时保留回指或拆成独立句，不臆造名称
- 注意中文特征：主题突出、意合衔接、主动优先
- 不为了规避标点规则而机械拆句
- 不把所有段落写成相同节奏
- 直接写具体困难、原因和后果，少用模板化转折
- "的"字不要连用三个以上

### 翻译腔和 AI 味
- 不堆叠名词，不滥用"进行""实现""基于"
- 不用英文语序，不用过多框式介词
- 不写空泛开头、泛化评价、套话结尾
- 不机械使用"不在于……而在于……"转折模板

## 规则

1. 默认在目标章节下写自然段，不修改结构标题。仅在用户明确要求段落节点模板，或目标文档明确把六级标题用作段落主题句节点时，才在第 6 级标题写内容；主题句与正文长度由任务和论证需要决定，上限仅在用户或文档规范明确给出时执行。
2. 有引用就引用，没有就标注 `[需要引用]`。
3. 不捏造数据。跳过无法验证的来源，并报告证据缺口。
4. 每个问题引用原文和位置。一个问题一条。
5. 只有网络使用已获授权且能力可用时，才通过搜索确认缺失；否则把结论标为未解决。

## 范围建议

### 分块协议（本文件只在此处展开）

- 交付单元是 Main 授权的一块，不是整份文档。Main 在新稿提纲或内容范围稳定时、或现稿修订开始时，按原文顺序建立分块清单，块标识为 `chunk-001`、`chunk-002` 等，每块记录目标文件、段落或页或 shape 范围和来源版本。任务没有给出块标识时，受派范围就是本次要处理的全部内容，不自行把整份文档拆开；五个章节不再是单次调用的长度边界。
- 中文单块最多 2,000 个非空白字符，超过即默认拆分。这个数字是保守的初始编排默认值，不声称测得最优值，不是交付物的篇幅限制，也不作为运行时门禁。按章节、连续自然段或连续页切分，不为凑满上限硬拼；段落、表格连同口径说明、公式与定义、代码与必要说明尽量完整保留，单个不可拆单元超限时单独成块并返回例外说明，不截断内容。
- 每块使用新的 `zh-writer` 子任务：不接着处理下一块，不恢复前块会话，不接收整份文档，也不接收其他块的往返历史。独立性不要求更换模型。不重叠的块可以并行，同时最多 4 个子任务，宿主容量较小时分批，容量为 1 时仍为每块新建上下文，同一文件的多块由 Main 单点集成。
- 输入是冻结风格包和验收项：用户原始要求、用途与读者、输出格式与模板、术语与主体用法、相关证据、只读邻接上下文，以及本块要保住的事实锚点、数字、术语、引用、结构标题和格式。风格包在块内不重新选择，用户显式指定的风格仍优先。
- 交付写块标识、来源版本、完整建议稿或有界 diff、保真检查和未解决问题。合格文字原样保留，不为证明执行过修订而改词。
- 默认只做一轮，指每块一轮写作、自检和有界修复，不是整份文档的一次往返。用户明确要求继续迭代时，仍在当前块内再进行一轮；块用完后终态交付，其余块由 Main 另派子任务。
- 不可修问题写入局限说明，不触发自动重试，也不阻止其他范围内的工作。
