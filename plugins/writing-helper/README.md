# writing-helper

Standalone OMP writing helper plugin with frugal-pi compatible writing skills, a model-backed `polisher` tool, deterministic writing checks, and local-first citation verification.


## What it provides

### OMP tools

The plugin registers four model-callable tools:

| Tool | Purpose |
| --- | --- |
| `polisher` | Polishes and de-AIs one prose passage: text in, rewritten text out. Stateless; reads no files, calls no tools, runs no agentic work, and rejects fenced code. Main calls it for every drafted passage and inserts the returned text verbatim. |
| `writing_logic_check` | Checks substantive writing logic: unsupported conclusions, data inconsistencies, terminology drift, causal leaps, and contribution/evidence mismatches. |
| `writing_quality_check` | Runs logic, style, citation authenticity, and optional semantic preservation checks. Citation findings are `VERIFIED`, `MISMATCH`, or `UNVERIFIED`. |
| `writing_ai_scan` | Runs the AIGC + Jev score ensemble: `0.325 * AIGC P(AI) + 0.675 * Jev P(AI)`, threshold `0.38`, with an optional slow-model fallback inside a `0.20` uncertainty band. The built-in keyword and statistical scan supplies supporting evidence and can run alone with `detector=local`. Advisory only. |

`polisher` accepts inline `text` plus an optional `language` (`zh`, `en`, or `auto`; it never translates) and is one model call with no file access. The three check tools accept inline `text` or a UTF-8 text `path`.
`polisher` and `writing_ai_scan` are active by default: the writing workflow calls
`polisher` on every drafted passage and `writing_ai_scan` after every completed
writing task and after each polisher repair pass; the other two tools remain
opt-in.

`writing_ai_scan` also reports the local density-normalized score, the metric
values behind it, and evidence-bearing findings. A custom `baseline` JSON object
maps terms to expected occurrences per 1000 tokens and overrides the built-in
reference rates for that invocation. The local score is supporting evidence, not
the ensemble label, and never rewrites the text.

The writing workflow calls `writing_ai_scan` on the final text of every completed
writing task before delivery, then reruns it after each polisher repair pass.
Findings are advisory and return to Main, which sends any wording change back
through `polisher`; the scan never rewrites the text and never decides
completion by itself.

The scan does not replace the sentence-level information-gain review. Neither the AIGC + Jev authorship score nor the local density metrics can tell whether a sentence adds a new fact, a necessary qualification, or a key logical relation — Main applies that self-check while drafting and the `polisher` prompt enforces it on each polished passage; when `writing_quality_check` is run, low-information-gain sentences come back as advisory clarity findings. Deleting redundant wording comes before explaining the same point again; unique facts, numbers, qualifiers, scope, modality, negation, citations, safety instructions, and reproducibility steps stay; and none of these tools rewrites the text.

### AIGC + Jev ensemble

`detector` defaults to `auto`: the ensemble runs when `allowNetwork` is true and
`AIGC_DETECTOR_URL` is set together with a Jev source (`TYPESAFE_API_KEY` or an
OMP judge model); otherwise the local scanner runs alone.
`detector=ensemble` fails closed when network access is not allowed or a setting
is missing; `detector=local` always uses the local scanner and never uses the
network.

| Setting | Purpose |
| --- | --- |
| `AIGC_DETECTOR_URL` | HTTP endpoint that accepts `{text, language}` and returns `{"aiProbability": 0.0-1.0}`. `AIGC_DETECTOR_TOKEN` is sent as a bearer token when set. |
| `TYPESAFE_API_KEY` | TypeSafe System One key for Jev. Optional when OMP has a usable `judge` role; the judge model is used otherwise. |
| `TYPESAFE_BASE_URL` | Optional TypeSafe base URL, default `https://api.typesafe.ai`. |
| `TYPESAFE_MODEL` | Optional Jev model, default `jev-latest`. |
| `SLOW_DETECTOR_URL` | Optional fallback endpoint that accepts `{text, language}` and returns `{"label":"human"}` or `{"label":"ai"}`. `SLOW_DETECTOR_TOKEN` is optional. |

The Jev prompt sent to TypeSafe is fixed and auditable:

```json
{
  "name": "authorship",
  "instructions": "Decide whether the text was written by a human or generated by an AI. Judge the writing itself, not the topic.",
  "criteria": {
    "human": "The text reads as human-written prose.",
    "ai": "The text has the statistical or structural signature of AI-generated prose."
  }
}
```

The AIGC classifier is language-routed outside this plugin: `yuchuantian/AIGC_detector_zhv3` for Chinese and `yuchuantian/AIGC_detector_env3` for English. The writing-helper package stays pure JavaScript; it calls the configured HTTP service and the Jev source, TypeSafe or the OMP judge model, and stores no credentials; OMP supplies judge credentials at call time.

Ensemble mode sends the full text to those configured services. The tool requires
explicit `allowNetwork=true` in addition to the environment settings; `auto`
falls back to local scanning without it, and `ensemble` fails closed. Use
`detector=local` when the document must not leave the machine.

From the repository checkout, the AIGC side can be started with the optional
reference server (requires `torch` and `transformers`):

```bash
python3 scripts/aigc-detector-server.py --port 8765
export AIGC_DETECTOR_URL=http://127.0.0.1:8765
# Optional when the OMP judge role is configured; the judge model is used otherwise.
export TYPESAFE_API_KEY=...
```

Then call the tool with `detector=ensemble, allowNetwork=true`.

The weights and threshold come from the core84 experiment. Those runs used
cached `opencode-zen/jev-1.13-free` outputs, not the shipped TypeSafe
`jev-latest` prompt shown above. The prior experiment scored 82/84 (97.6%; 0 FP, 2 FN)
and 94.46% in 5-fold cross-validation without slow; adding the slow fallback
scored 84/84 (100%) but is an upper bound on a public benchmark. Re-validate the
shipped prompt and model on a fresh set before claiming accuracy for this
implementation. The local scanner alone scored 43/88 (48.9%) on the in-domain
core set, so it is not a substitute for the ensemble.

The local style profile is calibrated on a small bilingual reference: pre-2020
human articles and 2026 AI-written web articles. It compares function-word rates,
pronoun rates, punctuation, word length, nominalization, and sentence shape
against that reference and reports the top deviations. Genre can move the
profile, so treat a high score as a reason to inspect the evidence, not as proof
that a text is AI-generated. Source URLs, per-document results, reference
means/SDs, and directional weights are in `calibration/ai-scan-profile.json`;
`scripts/ai-scan-calibrate.mjs` recomputes them from a cleaned corpus.

For an advisory semantic-preservation comparison, pass the revised `text`, the
prior `originalText`, and either `preservation: true` or
`checks: ['preservation']`. The result reports changed qualifiers, modality,
polarity, numbers, citations, and LaTeX anchors. Drift findings never make the
tool call fail or control whether editing may continue.

### Slash commands

The plugin registers three slash commands:

```text
/writing-logic paper.md
/writing-quality paper.md
/writing-ai-scan paper.md
```

Supported command flags:

| Flag | Applies to | Meaning |
| --- | --- | --- |
| `--redline` | both | Use final-pass mode with fewer style-only findings. |
| `--standard` | both | Use broader standard review mode. |
| `--lang zh|en|auto` | both | Force or auto-detect language. |
| `--max N` | both | Limit returned issues. |
| `--checks logic,style,citation` | quality | Select quality-check categories. |
| `--bib path/to/refs.bib` | quality | Load BibTeX bibliography evidence. |
| `--literature path/to/literature.md` | quality | Load local literature evidence records. |
| `--allow-network` | quality, ai-scan | Allow external citation lookup or the AIGC+Jev network call for this invocation when host and user permissions already allow it. |
| `--no-network` | quality | Explicitly keep external citation lookup disabled. |
| `--disable-network` | quality | Alias for `--no-network`. |
| `--citation-providers local,doi,arxiv,crossref` | quality | Select lookup providers; `local` suppresses all external lookups. |
| `--baseline '{"term":0.1}'` | ai-scan | Override reference rates with expected occurrences per 1000 tokens. |
| `--no-keywords` | ai-scan | Run only the statistical scan. |
| `--detector auto|ensemble|local` | ai-scan | Select ensemble-first auto mode, fail-closed ensemble mode, or local-only diagnostics. |

Slash commands are path-oriented. Use the tools directly when you need inline `text` input.

## Citation verification model

`writing_quality_check` treats citations conservatively:

- `VERIFIED`: evidence confirms the citation metadata.
- `MISMATCH`: evidence contradicts the bibliography or citation metadata.
- `UNVERIFIED`: no evidence source confirms the citation.

`UNVERIFIED` does not mean fabricated. It means the check had insufficient evidence.

The citation check uses local evidence first:

1. Inline `bibliography` from tool input.
2. `bibliographyPath` / `literaturePath` from tool input.
3. Colocated evidence files for a document path:
   - `<document-base>.bib`
   - `refs.bib`
   - `references.bib`
   - `paper.bib`
   - `literature.md`
4. External DOI/arXiv/Crossref lookup only when citations remain unverified and the caller explicitly passes tool input `allowNetwork: true` or the `--allow-network` command flag.

External lookup is disabled by default. `allowNetwork: true` and `--allow-network`
express the caller's request for remote lookup; they do not grant network access
or replace OMP host and user permissions. Exposing the tool through
`/enhancer-tools` is likewise not network permission. The compatibility flags
`--no-network` and `--disable-network`, or tool input `allowNetwork: false`, keep
lookup disabled explicitly.

Passing `citationProviders: ['local']` (or `--citation-providers local`) pins the
citation check to local-only mode: all external DOI/arXiv/Crossref lookups are
suppressed even when `allowNetwork: true` is set.

## Bundled frugal-pi compatible content

### Polisher

`polisher` is a tool, not an agent. It makes one stateless model call per passage
and resolves its model from `modelRoles.polisher`; when that role is unset it
falls back to `@tiny`, then `@smol`, then the session's current model. It ships
active, so no `/enhancer-tools` activation is needed. It exposes no tools and no
file access, runs no agentic loop, does not summarize, translate, restructure, or
review facts, and rejects fenced code with `code_not_supported`. Main splits code,
equations, and citation mechanics out first and calls it once per bounded prose
passage; the returned text is inserted verbatim.

Prompts live in `polisher/prompt-en.md` and `polisher/prompt-zh.md`. Language
`auto` detects the passage language and picks the matching prompt; the tool never
translates between them.

`polisher/prompt-zh.md` 承载中文书写基线：规范、自然的书面表达，段首先写问题、对象或任务，动词具体并带方法层级，机制随方法交代，结果句带数字、量级与比较对象，主语按任务和材料指定，句长与标点服从信息关系，不机械拆句。科研叙述体只在科研成果凝练与学术正文里启用，增加针对式开段、结果显示引出、写明具体作用对象和范围的贡献收尾，以及承载必要限定与条件的长复句；贡献收尾、量化成效和必要长复句的豁免只在这两类任务里生效，量化成效必须有实测和比较基准，其他文体不豁免，意义拔高照常报告。文体卡决定内容组织、读者适配和示例范围，与书写基线同时适用；两处出现实质冲突时按任务用途和材料判断并说明取舍。技术说明、教学讲解的参照选段与六张文体卡（五张既有卡加一张幻灯片正文卡）存放在 `plugins/writing-helper/skills/plain-chinese-writing/references/style-profiles.md`。用户逐任务指定的风格、术语和篇幅优先。参照文本只作风格参照，不作为事实、引用或案例来源。

`polisher/prompt-en.md` 的内置英文技术散文基线采用用户指定的基准文本；所有英文润色默认按该文风输出，用户显式给出另一种风格或原文风格更合适时以用户为准。基准文本只用于模仿文风，不作为事实、引用或案例来源。

`writing` is the single marketplace writing workflow, and Main does its writing
work directly. Main drafts every prose and copy surface, calls `polisher` once per
bounded passage, inserts the returned text verbatim, and then runs the advisory
read-only checks (`writing_quality_check`, `writing_logic_check`,
`writing_ai_scan`) and decides the disposition of their findings. Any later
wording change, including one motivated by an orphan line, clipping, overflow, or
spacing, goes back through `polisher`; Main never rewords polished text itself.
If `polisher` is unavailable, Main records the limitation instead of shipping
unpolished prose. This remains Agent-selected soft guidance, not a fork
requirement, router, gate, or automatic repair loop.

## Installation

Recommended installation uses the OMP marketplace so future releases can be upgraded with `omp plugin upgrade`.

Add the root monorepo marketplace:

```bash
omp plugin marketplace add marapapman/omp-enhancer
```

Install the plugin:

```bash
omp plugin install writing-helper@omp-enhancer
```

Check the installed plugin list:

```bash
omp plugin list
```

If the plugin is disabled, enable it:

```bash
omp plugin enable writing-helper@omp-enhancer
```

Restart the OMP session after installation. Marketplace installation exposes the tools `writing_logic_check`, `writing_quality_check`, and `writing_ai_scan`, plus the namespaced commands for this plugin.

## Upgrade

Update the root marketplace catalog, then upgrade the plugin:

```bash
omp plugin marketplace update omp-enhancer
omp plugin upgrade writing-helper@omp-enhancer
```

If you are developing locally, keep using `omp plugin link` instead of the marketplace upgrade flow.

## Document input boundary

The plugin reads UTF-8 text files. Markdown, plain text, and LaTeX source are appropriate inputs.

It does not decode binary Word or PDF files directly. Convert `.docx` or `.pdf` content to text first, or call the tools with inline `text`.
