# `writing` workflow reference

Optional advisory reference. Main orchestrates freely.

- When: Prose and copy in any language (English, Chinese) or format (LaTeX, Markdown, Beamer, Word, PowerPoint/PPTX): the dedicated text tools writer/zh-writer author every wording surface, while Main/task handle code, evidence, structure, layout, conversion, and validation.
- Skills: `writing-review`, `format-humanizer`, `plain-chinese-writing`, `zh-research-achievement-writing`, `zh-format-humanizer`, `zh-writing-review`, `zh-writing-polish`, `writing-markdown-helper`, `zh-writing-markdown-helper`, `format-markdown2latex`, `format-latex2markdown`, `format-template-latex`, `latex-beamer-slides`, `beamer-to-powerpoint`, `slides-storyline`, `storyline-workbench`, `docx`
- Agent candidates (host runtime adapter labels): `writer`, `zh-writer`, `checker`, `zh-checker`, `task`.

Text capability note: `writer` and `zh-writer` are the dedicated language-matched text tools for all English/Chinese prose and copy; they appear under their packaged Agent adapter names only because the current OMP host exposes model workers that way. That backend label is not a second general-purpose writer agent and grants no code or file permissions; Main/task own code and other non-text actions.

## Required step order

These steps are the required execution order for this domain. The plugin provides no runtime gate, router, or completion condition — that means the runtime never blocks you, not that the steps are optional. Skipping a named step without a stated reason is a workflow violation; report it in the final delivery.

1. Identify target language (zh/en) and format (plain/LaTeX/Markdown/Beamer/Word/PowerPoint/PPTX).
2. Load matching language and format skills.
3. For Chinese prose, prepare the genre reference before drafting by picking the card that matches the task purpose (technical explanation, teaching, academic body text, research-achievement summary, everyday communication, or slide body 幻灯片正文) from skill://plain-chinese-writing/references/style-profiles.md and handing it to the zh-writer assignment together with the target readers, the selectable excerpt and its source, and the separately marked fact material, because the baseline itself is universal across Chinese writing while the research-narrative register activates only for the two research cards (academic body text 学术正文 and research-achievement summary 科研成果凝练), and the card supplies content organization and the excerpt; reading that reference is genre material retrieval that does not activate the plain-chinese-writing Skill, so skills=none stays valid for the writer.
4. The substantive-text sequence starts with a proposal from the language-matched dedicated text tool, writer (English) or zh-writer (Chinese), covering drafting, logical/semantic revision, translation, polishing, titles, labels, captions, notes, and UI copy; before drafting a new outline or revising an existing draft, Main builds a chunk list in source order, with Chinese chunks at most 2,000 non-whitespace characters, English chunks at most 1,200 words, and slide chunks at most 6 pages, splitting by section, consecutive paragraphs, or consecutive pages and never padding a chunk to reach the limit, keeping a paragraph, a table with its scope note, a formula with its definition, and code with its needed explanation intact, and letting an indivisible unit over the limit become its own chunk with the exception recorded and no content truncated; every chunk goes to a new writer/zh-writer sub-task that never continues the previous chunk, never resumes its session, and never receives the whole document or another chunk's round trips, and this chunk independence never requires a different model; at most four such sub-tasks run at once, and a host with less capacity batches them while still creating a new context per chunk. Each draft follows the target body language's built-in reference style carried by that matching text tool; mixed-language content uses separate writer and zh-writer text-tool calls by segment; Main preserves semantic anchors and integrates the returned proposal verbatim.
5. Checker/zh-checker review, when used for early feedback, reports logic/evidence issues and sentences that add no new fact, a necessary qualification, or a key logical relation without rewriting prose; it is not the final review — the scan step below runs before the final checker review and delivery — and any substantive repair returns to the same language-matched text tool. Main integrates exact writer output, while Main/task/checker never rewrite prose; code, evidence collection, structural reordering, layout, conversion, validation, and other non-text actions may remain with Main/task.
6. If the writer text tool cannot safely handle substantive English prose (or zh-writer Chinese prose), record that inability as a limitation rather than silently drafting through another role.
7. For Word output, apply the approved writer/zh-writer content through officecli (docx skill) and verify with officecli validate and a rendered view; task may perform only structural, layout, conversion, and validation operations and must not change wording.
8. For a new article or a new slide deck, build and confirm the story as a tree in the storyline-workbench site before any prose; the site freezes the confirmed tree and its open comments into an immutable round snapshot, the language-matched writer/zh-writer writes from that snapshot, and an already confirmed story can be loaded into the site for another round.
9. For new Beamer decks, the writer/zh-writer text tool produces the Markdown content plan whose titles avoid the "XX：XX" label+colon+label pattern and read as coherent prose in deck order; confirm it with the user, let a separate task reconcile slide order and structure, then have the task convert the unchanged text-tool output into Beamer and begin layout.
10. After either a new or existing Beamer deck reaches its final validated Beamer visual revision, branch optionally to PPTX output when requested: use the fixed external `beamer2pptx` Skill/repository at https://github.com/xdmlxdml/beamer2pptx/tree/main/beamer2pptx with the final validated PDF and corresponding `.tex`, macro, and font sources when available; a producing task performs only PPTX conversion, binding, rendering, and bounded fixes, then one independent read-only reviewer checks the current PPTX renders. The producing task may apply at most one bounded fix, rerender fresh evidence, and the same reviewer confirms only those findings once. Keep this branch advisory with no automatic loop or hard gate; preserve visible content, formulas, slide order, and Markdown/Beamer sources. A content or layout finding is resolved in place at the stage where it is found; it is not propagated back to the Markdown content plan; a prose wording change is still produced by the language-matched writer/zh-writer text tool and applied in place only as that verbatim proposal; task authors no wording.
11. For substantial de-AI work, apply the format-humanizer/zh-format-humanizer rules one at a time before checking: a scan task inventories the tell families present, then one writer/zh-writer text-tool pass per found family runs over bounded chunks, with the non-overlapping chunks of that family dispatched as separate fresh writer/zh-writer sub-tasks that may run in parallel; the family passes run strictly sequentially, and the next family starts only after every authorized chunk of the current family is complete and its semantic-anchor check verified by Main; all rewriting stays with the text tools and no pass mixes families.
12. After every completed writing task, once the language-matched text tool has run its sentence-level information-gain and absolute-scope self-checks on its own final text, call writing_ai_scan with detector=ensemble and allowNetwork=true on that text before checker review and delivery; when it reports a tell family, route one language-matched writer/zh-writer repair pass per family and rerun the scan on the revised text, and after any other writer repair — including wording changes motivated by orphan lines, clipping, overflow, spacing, or other layout findings — the writer reruns the sentence-level information-gain and absolute-scope self-checks on the exact final wording before the scan and the checker/zh-checker review of the integrated text. When the ensemble scan cannot run or errors, record it as "ensemble unavailable" or "ensemble failed" and record any local fallback result separately under its own label; a local fallback never marks the ensemble checkpoint or TODO complete, and this advisory chain adds no runtime gate and no automatic retry loop. Record the last scan result and its AIGC+Jev decision with the delivery; the scan is advisory evidence, not a quality verdict, and neither the authorship score nor the local metrics can replace the sentence-level information-gain review.
13. Check via checker/zh-checker for substantial work to report logic, semantic, evidence, and clarity issues, including sentences that add no new fact, a necessary qualification, or a key logical relation, all read-only and without rewriting prose; a generic task, diff-review, or visual review never substitutes for this required final checker/zh-checker review on substantial writing, and after a layout-motivated writer repair the integrated final text still receives it once the writer has rerun the sentence-level information-gain and absolute-scope self-checks on the exact final wording; after chunked integration, run a read-only consistency check covering each chunk's fidelity and style against its own source, every adjacent pair's referent and continuation, document-wide terminology and subject use, repeated closers and page templateization, and style coverage across the opening, middle, and closing chunks; that check may be split across chunks so no single checker receives the whole document, each problem is located to a specific chunk, and every wording repair still goes to a new writer/zh-writer sub-task with no final whole-document polish pass; Main checks orchestration, preservation, and consistency only and never authors or edits text.
14. Deliver with preservation and consistency verification.

## Scope notes

- Language selection: detect the target body rather than the instruction language; route English text to the dedicated text tool writer and Chinese text to the dedicated text tool zh-writer, using both for mixed-language content.
- The language-matched text tool carries a built-in base style for its language; a user-specified genre, length, terminology, template, and factual anchors win over that base style, and the base style never bends, invents, or drops evidence to fit itself.
- The Chinese built-in baseline now has two layers that apply to all Chinese prose and copy: a universal layer of plain natural written Chinese, and a research-narrative register that is the default only inside the 科研成果凝练 and 学术正文 cards; the universal layer opens each paragraph with the problem, the object, or the task rather than empty background, takes the actor that the task or material names as the grammatical subject (a person, a team or project name, a system name, 本人, 我们, or 本文; the request may therefore set it, and when nothing is specified the fallbacks are 本人 for personal materials, 本文 for papers, 我们 for team work, and the system name as the carrier; one document keeps a single subject identity), uses concrete verbs that state the method mechanism instead of only announcing the method name, and writes results with a number, a magnitude, and a comparison target while keeping the stated qualifiers and writing an unmeasured result as 未测 instead of extrapolating; the research-narrative register opens paragraphs with the problem stated as 针对 or with the field scope, leads results with 结果显示 or 结果表明, closes with an evidence-backed contribution naming the affected object and scope, keeps necessary long compound sentences, and joins multiple results of one topic with semicolons or 以及 while different topics stay in separate paragraphs; the baseline owns wording and syntax, while content organization, reader adaptation, and example scope stay with the genre cards (技术说明, 教学讲解, 学术正文, 科研成果凝练, 日常沟通, 幻灯片正文); the three exemptions from the phrasing bans (contribution closers with a named object and scope, quantified effect statements carrying a measured number and a baseline, and necessary long compound sentences carrying qualifiers) apply only inside the 科研成果凝练 and 学术正文 cards, and every other genre keeps the full phrasing bans; the 技术说明 card references 阮一峰《ES6 入门教程》 (https://wangdoc.com/es6/let , 「let 命令 / 基本用法」) and the 教学讲解 card references 《Hello 算法》 (https://github.com/krahets/hello-algo/blob/main/docs/chapter_array_and_linkedlist/array.md , 「扩容数组」), and the 学术正文 card now carries a user-supplied personal research sample; the selected excerpt is style material only, never a fact source, and facts come only from the separately marked fact material; the zh-writer assignment carries the target readers, the full card for the current genre, the selected excerpt with its source, the specific points to learn, and the fact material separately marked, and an author name, a URL, or an empty path is not a handoff; when the source is unreachable, the excerpt range has changed, or the user forbids network access, use the card plus the built-in requirements and record in the delivery that no excerpt was loaded, without inventing an excerpt or silently switching authors; when the card file itself is missing, use the built-in requirements, report the missing path, and continue the rest of the writing safely; the checker and every de-AI revision round receive the same style package and report specific deviations with their effect on the current purpose instead of demanding a rewrite from an abstract naturalness score.
- LaTeX/Beamer/Word/Markdown are format overlays, not separate workflows; select matching format skills.
- Short copy and format surfaces (titles, labels, captions, interface copy, slide bullets) still compress within their own format constraints and are not required to carry all three of problem, method, and result, but they never drop a result or its qualifiers for the sake of brevity when they do state one; the grammatical subject follows what the task or the material specifies, a specific person, a team or project name, or a system name, and a user-specified subject is never overridden; only when neither the user nor the material specifies one does the subject fall back to 本人 for personal materials, 本文 or 我们 for papers and team work, or the work carrying the result; when revising existing prose that the user has not asked to re-style, keep the original wording and register instead of rewriting it wholesale into the narrative register; a style, terminology, or length the user specifies for the current task takes precedence over the baseline, and factual anchors and hard phrasing bans hold unchanged.
- A zh-writer assignment brings together the universal Chinese writing baseline with its colloquial-word ban contrast, the corresponding genre card for the current purpose including the 幻灯片正文 card, the selected excerpt with its source, and the separately marked fact material; the research-narrative register is appended only for the 科研成果凝练 and 学术正文 cards, and the three exemptions from the phrasing bans (contribution closers, quantified effect statements, and necessary long compound sentences) hold only inside those two cards, where the contribution closer names its object and scope, the quantified effect statement carries a measured number and a baseline, and the long compound sentence carries the necessary qualifiers, while every other genre keeps all the bans in force. 日常沟通 copy keeps the form of address and the action it asks of the other party; short copy compresses within the format constraints of its own surface.
- Word (.docx) documents are produced and edited through officecli (single binary, no Office install): create/draft content via the language-matched text tool (writer/zh-writer), apply it with officecli add/set, then verify with officecli validate and view issues, and render view html/screenshot for visual confirmation before delivery. officecli also covers .xlsx and .pptx, and its merge command fills {{key}} templates from JSON.
- Every English or Chinese prose/copy surface is authored only by its language-matched dedicated text tool, keeping text authorship writer-only: drafting, revision, translation, polishing, titles, labels, captions, notes, narrative copy, and UI copy start with a writer/zh-writer proposal; Main preserves semantic anchors and integrates the returned text verbatim; checker/zh-checker reports logic/evidence issues without rewriting prose; any substantive repair returns to the same language-matched text tool. Main/task own code, evidence collection, structural reordering, layout, conversion, validation, and other non-text actions and never rewrite prose.
- Information-gain principle, always on for every prose and copy surface in every language, including when no Skill is loaded: each sentence serves one clear expressive focus and keeps only what adds a new fact, a necessary qualification, or a key logical relation; do not re-explain what the reader can infer from the surrounding text, do not use modifiers with no information gain, do not narrate a process step by step only for completeness, and allow a reasonable omission so the reader completes the simple inference — when revising, delete the redundant wording before writing more words to explain the same point. Deletion removes redundant expression, never unique evidence: a focused sentence may carry several necessary clauses, so the rule never forces one fact per sentence or uniformly short sentences, and unique facts, numbers, units, qualifiers, scope, modality, negation, causal direction, citations, safety instructions, reproducibility steps, and task-required content all stay. When Main extracts semantic and factual anchors for a writer assignment, abstract restatements and concessive empty closers are not independent facts to preserve, so the underlying fact is kept while the empty close is deleted, even if the source text or an earlier assignment explicitly lists the closer itself as required content. The language-matched text tool applies the principle while drafting and revising, so the writer self-check runs before the ensemble scan; checker/zh-checker reports violations read-only in the clarity review when that review is used; neither the AIGC+Jev authorship score nor the local scanner metrics can replace this sentence-level review, which stays advisory method guidance rather than a runtime gate or an authorship verdict.
- If the language-matched text tool cannot safely handle substantive prose, record the inability as a limitation and do not silently draft through another role.
- For new Beamer decks, build and confirm the deck story in the storyline-workbench site, then have the writer/zh-writer text tool write the per-page Markdown content plan from that confirmed snapshot; the content plan decides each page's form, and a table is proposed only when it serves comparison or lookup on that page, so the same page does not repeat the table row by row in prose; after the user confirms each page's content, a separate task reconciles the slide order on the unchanged plan (no content overlap, semantically coherent modules, logical overall progression; page titles avoid the "XX：XX" label+colon+label pattern and read as coherent prose in deck order; reconfirm only on material reorders; unfixable crossings return to Markdown reconfirmation) before task converts the plan into Beamer and begins visual authoring and basic layout. Plan→Beamer is forward, one-way, and explicitly requested; the Markdown plan is the source for that explicit generation and Beamer .tex files are derived layout artifacts of that pass. Three independent editing modes — storyline-only (plan), Beamer-only (.tex/PDF), and PPTX-only (.pptx) — keep ordinary edits inside the chosen target; the target's current revision is the edit baseline, counterparts are read-only context, divergence does not trigger realignment, and an isolated edit never propagates silently forward or backward.
- The storyline-workbench site is the story-organization step for a new article or a new slide deck; an already confirmed tree stays editable there for later rounds, and local polishing, translation, or edits to an existing finished document keep that document's own revision as the baseline and do not start a new tree.
- Each leaf is one article paragraph or one deck page titled with its topic sentence; the root holds the whole topic, and chapters and sections group the leaves. A slide plan writes one page per leaf in tree order and records that leaf ID in `sourceNodeIds` together with `storyRevision`, while an article turns chapters and sections into headings and each leaf into one paragraph from the exported snapshot.
- Direct PPTX editing is distinct from PPTX as a Beamer output: editing an existing .pptx is the PPTX-only mode and goes through the officecli-backed docx flow; an isolated PPTX edit does not regenerate from Beamer. The optional Beamer→PPTX path (fixed external beamer2pptx Skill/repository) consumes the final validated Beamer PDF as the visual authority and does not consult or update the Markdown plan.
- Chinese slide copy follows the 幻灯片正文 card (one job per page, at most three bullets, complete short sentences, no contribution closer, and no forced 针对 opener or 结果显示 lead) and uses plain-chinese-writing for natural sentences, zh-format-humanizer for AI-like phrasing, and zh-writing-review for page-level clarity; the research-narrative register does not apply to slide copy; English slide copy uses format-humanizer for AI-tell removal and writing-review for page-level review; use zh-writing-polish only for actual polishing and never replace body prose with keyword or phrase lists.
- Every writing task ends with a writing_ai_scan check with detector=ensemble and allowNetwork=true on the final text before checker review and delivery; the scan is advisory evidence rather than a gate, findings return to the language-matched text tool, and the last scan result is recorded with the delivery. When AIGC_DETECTOR_URL is missing, no Jev source is available (neither TYPESAFE_API_KEY nor an OMP judge model), or the tool is unavailable, record that limitation instead of substituting a keyword-only or local-only judgement. When the ensemble scan itself cannot run or errors, record it as "ensemble unavailable" or "ensemble failed"; any local fallback runs only as a separately labelled record and never marks the ensemble checkpoint or TODO complete, and nothing in this note adds a runtime gate or an automatic retry loop.
- De-AI is one-sighting in every language: any listed tell justifies an edit on its first appearance — prefer an over-correction to a miss ("宁可误杀，不可放过"). Only quotations, titles, proper names, passages discussing a phrase rather than using it, text predating November 30, 2022, and details that carry the writer's voice (specific unusual details, mixed feelings, first-person choices) are exempt.
- De-AI application is per-rule, not one mixed pass: for substantial documents, first run one scan task that inventories which tell families actually appear (contrast-repetition, one-line closers, sayings that sound deep, staged run-up, arguing with no one, forced triads, repeated openings, dashes, stacked qualifiers, hyphenated pairs, passive/missing subjects, symmetrical paragraphs, inflated words, inflated significance, -ing riders, sales language, borrowed authority, vague connection, copula avoidance, bold decoration, decorative headings, curly quotes, chatbot residue, knowledge-limit disclaimers, repeated headings, writing about previous versions, anaphoric passive riders; zh: 否定式对偶、单句收尾、貌似深刻的说法、铺垫式开场、与不存在的对手辩论、意义拔高、理解承诺句、抽象复述回声、宣布式过渡、节奏对仗收尾、回指被动尾句、及弱特征清单), then run one writer/zh-writer text-tool pass per found tell family over bounded chunks. Inside one family the non-overlapping chunks run as separate fresh writer/zh-writer sub-tasks and may run in parallel; the next family starts only after every authorized chunk of the current family is complete and its semantic-anchor check verified (限定/模态/范围/否定/方向/数字/引用 unchanged; no fact added or dropped). A family's round becomes the new accepted version only when all its authorized chunks are done, so no later family or the user ever sees half old and half new text. Each chunk pass handles only its one family on that chunk's bounded text and returns SEARCH/REPLACE blocks or a diff; Main owns file effects. Skip families the scan did not find.
- Hard phrasing bans in every deliverable (prose, slides, figures, documents): no "不是X，而是Y" contrast-repetition construction or its English equivalents ("not X, but Y", "not just X") — state the claim once, directly, with no restatement in inverted or synonym form; no opening or closing one-sentence summary that restates what the text just showed; and, in structured artifacts, no "XX：XX" label+colon+label titles or label-colon bullet lead-ins, and no claim or label spliced onto a colon in titles, bullets, or captions (a colon is allowed only before an enumeration of three or more items, a definition, a formula, or code, and split captions "Left: …; Right: …" are rewritten as complete sentences). These are fixed whenever found, not clustering-gated tells. Verbatim quotations and cited material are exempt.
- Hard phrasing bans in every deliverable also cover the setup then emphasis then restatement pattern, where one sentence sets up, a second emphasizes the same claim, and a third restates the same idea in other words, so the sentence carrying the fact is kept and the restatement is deleted; and unscoped absolutes, where all, any, only, always, never, every, must, exactly, and their Chinese equivalents 都, 只能, 任何, 一定, 必然, 始终, 绝不, 全部, 唯一 are kept only when the stated scope is present and matches the evidence and otherwise narrowed or deleted with the scope, the exception, or the untested case stated. These two patterns are fixed whenever found, not clustering-gated tells. Verbatim quotations and cited material are exempt, and qualifiers and preconditions are not collateral: necessary conditions, scope, data provenance, measurement conditions, and untested cases are never deleted along with the offending restatement, and these bans are never a length cap, never a gate, and never a reason to drop a semantic anchor.
- Hard phrasing bans also cover anaphoric passive riders, 回指被动尾句: 完整主句后用逗号接「前置宾语＋由＋回指施事＋动词」的小句，把同一次操作里的另一个动作另起一截（「Documents 和 report.txt 拼成一条路径，斜杠由它补上。」）。把尾句的动作和新对象并进主句，用「并」接在主句动词后面；施事能从前文还原就写一次名称，还原不出来保留回指或拆成独立句，不臆造名称。纯重复归 S13，本族只处理带动作或新对象的尾句。 English §38 reads: **§38 Anaphoric passive riders.** A complete main clause followed by a comma and a `with` phrase in the shape with + object + past participle + by + an anaphoric actor; the `with` phrase is a participial adjunct, never a finite clause, and the rider carries the operation's second action behind an anaphoric actor. Before: "Documents and report.txt are joined into one path, with the separator added by it." After: "The function joins Documents and report.txt and adds the separator." The fix merges the rider's action and new object into the main clause; no deletion branch exists. Write the actor's name once only when it is recoverable from the main clause or earlier context; when it is not recoverable, keep the anaphor or split the rider into an independent sentence, and never invent an actor. §36 covers pure repetition, §18 covers shallow -ing riders, and §38 covers anaphoric passive riders carrying an action or a new object. Exemptions: independent sentences, explicit non-anaphoric actors, quotations, proper names, and code; no blanket exemption for interface documentation or technical passive voice. This is fixed whenever found, not clustering-gated.
- No "specifics then sweep" summary clause: do not follow a concrete factual clause with a summarizing clause that elevates it to a sweeping whole ("……。这些共同构成了……/这一切标志着……/正是这些……成就了……"; English "Together, these ...", "All of this marked ...", "It was these ... that ..."). The tell has two faces: the second clause adds no new fact, only inflation; and its skeleton mirrors the first clause (same object, scope adverb, agent, completion verb), forming a loose pseudo-parallel couplet. This is the documentary-narration "画面＋全称升华" two-beat sentence — a stock template of AI-written popular history. Fix by keeping the concrete clause and cutting the sweep, or by replacing the sweep with a real fact.
- No "understanding promise" transitions ("理解了 X，Y 就好懂了", "把这个说清楚，A、B 和 C 就容易理解了", "X is the key to understanding Y"): an empty promise about the reader's future comprehension with no stated dependency — delete it, or state the real dependency concretely ("A、B、C 都以 X 为基础"), or, when the text really covers the listed items in order, write the roadmap instead ("先讲 X，再看 A、B 和 C"). This is fixed whenever found, not clustering-gated.
- No abstract-restatement echo ("算筹、算盘就能做加减乘除。" followed by "“会算”这件事人类很早就做到了。"): the second clause repeats the first at a higher abstraction level with zero information gain. This is the sibling of the "specifics then sweep" ban without the sweeping whole — the test is the same two-beat skeleton (concrete fact, then a quoted-or-nominalized abstraction of that same fact). Fix by keeping the concrete clause and deleting the echo, or replacing it with a fact that actually advances the text. Never wrap a common-sense statement in quotation marks or nominalize it into a concept object ("“会算”这件事") — writers do not put scare quotes around their own commonplaces. This is fixed whenever found, not clustering-gated.
- No "the real question is" announcer transitions ("新的问题是……", "真正的问题是……", "这就引出了一个更深的问题……", "The real question is ..."): the writer does not declare on the reader's behalf which question matters next; the facts themselves carry the transition, or a concrete dependency states it ("在此基础上，还剩两个障碍"). Announcing significance is narration-voice, natural when spoken in a lecture and filler once written down. This is fixed whenever found, not clustering-gated.
- For Beamer/PPT titles, body, captions, labels, notes, and narrative copy, no announcer transitions used only as stage announcements (including "The real question is", "A new question is", "This raises a deeper question", "Let us turn to", "新的问题是", "真正的问题是", "这就引出了一个更深的问题", and "接下来我们看"); let facts or a concrete dependency carry the transition instead.
- For Beamer/PPT titles, body, captions, labels, notes, and narrative copy, no unsupported hollow significance/evaluation assertions (including "this is important/significant/transformative", "this demonstrates the power/value", "意义重大", "具有重要意义", "标志着", "彰显了", "开创了", and "充分说明"); state concrete evidence, scope, or source instead, and retain significance/evaluation only when that support is stated.
- No rhythm-matched paired-phrase closer: do not end a sentence, paragraph, or slide with two or more neatly matched phrases ("够不够快、能不能自动", "更便宜、更安全、更可控", "faster, cheaper, better") unless each named item is a real, independently justified dimension of the claim. Matched rhythm is earned by content, not composed for cadence. If one of the parallel items would be cut without losing meaning, cut the whole flourish and state the single point plainly. This is fixed whenever found, not clustering-gated.
- No didactic cognition directives in any deliverable: cognition verbs with resultative complements aimed at the reader or the text itself — zh: 分清楚、分清、看清楚、看清、看明白、认清、想清楚、想明白、搞清楚、弄清楚、理清楚、理顺、捋顺、记住、请注意、要注意、别搞混、不要混淆、吃透、掰开揉碎、把握好、划重点、这就说清楚了、至此脉络理清了、想必你已经明白，以及绝对化补语 定死、框死、锁死、堵死、卡死、限死; en: "distinguish clearly", "see clearly", "keep in mind", "remember that", "note this carefully", "don't confuse X with Y", "this makes it clear", "now the picture is complete", "nailed down", "locked in". State the distinction, the conclusion, or the analysis itself; when a command precedes real analysis, delete the command and keep the analysis; when expressing a fixed choice, give the concrete value or constraint and say which parts remain adjustable. Exemptions: legitimate instructional registers (step-by-step manuals, dialogue, interactive teaching), fixed technical terms ("写死", "lock-free"), quotations, and proper names. This is fixed whenever found, not clustering-gated.
